# Control Slimming, 2026-11

Record of the 2026-11 slimming campaign: what was removed, why, the evidence
for each removal, and how it was verified. One section per pull request.

- Audit report (scope, numbers, method): Claude Doc
  "Control 瘦身审计报告", 2026-11-22.
- Decision (owner, 2026-11-22): delete class A (no runtime caller) and class
  B (never enabled in production); class C (structural) gets a design first.
- Out of scope here: v2board naming and table prefixes (separate campaign,
  #572/#573), commercial seams used by the private overlay (kept, listed
  below).

## Method

Every removal needs one of these proofs, recorded per item:

1. **Unreachable**: `deadcode` (golang.org/x/tools v0.53.0, built with
   go1.26.11) reports the function unreachable from `cmd/...` both with and
   without `-test`, or reachable only from tests.
2. **No caller**: a word-boundary search for the symbol finds no reference
   outside its definition and its own tests in this repository and in
   anix-agent, anixops-ansible, anix-control-commercial, anixops-speedtest
   and anixops-website.
3. **Route never answered success**: for an HTTP route, the handler only ever
   returned an error, and no client (web/src, anix-agent, ansible) calls it.

Not removed even when unreachable:

- Methods called by reflection or through an interface: `TableName`,
  `String`, `GoString`, gorm hooks.
- Test seams and test oracles (`*ForTest`, `Set*`/`Reset*` used by tests,
  `KnownKinds`, `BulkActionRoutes`, `GetProtocolTemplates`).
- Functions the commercial overlay calls (`GenerateInviteCode`,
  `GenerateUserInviteCode`, `InviteCodeLockKeys`, `LockUserInviteCodes`,
  `PlanSnapshotFromPlan`, `GetByType`, `SetConfig`, `GetUserInviteCodes`,
  `SaveConfig`) and the overlay's registration seams
  (`registerContributedWorker`, `registerRouteContributor`,
  `RegisterDashboardContributor`, `packages/builtin` `Register`/`Host`).

Scripts and raw evidence (route table dump, deadcode output with line spans,
frontend export scan) are kept with the audit report.

- No schema change, no migration, no API change.
- The release pipeline loses one tag gate, which only covered the removed

## PR 2d: remote module runtime (class B4)

Base: `main` at dbe2911. About 120 files; 3,994 non-test Go lines and 1,928
Go test lines deleted (165 and 109 added), plus about 1,000 lines of
deployment files, CI steps and smoke scripts.

### Motive and evidence

The remote module runtime let a package run as its own container instead of
a child process of Control: it enrolled with the kernel CA, bound to a
kernel listener (`module_runtime.listen`, `:7443`) and served the host
protocol over mTLS. Production never used it, and nothing outside this
repository speaks it.

- **Never enabled.** Production (PL, FR standby) is installed by
  anixops-ansible, whose Control configuration sets no `module_runtime.*`
  key except `ca_kek` (searched: anixops-ansible, anix-agent,
  anix-control-commercial, anixops-website, anixops-speedtest). Without
  `module_runtime.enabled` the listener never started, no package could be
  switched to `remote` (`module_runtime_disabled`), and the enrollment and
  runtime tables stayed empty.
- **No client.** No web page calls the module routes (`web/src` has no
  `kernel/modules` reference); the commercial overlay calls only
  `modulesdk.Run` and never reads `Host.Remote` or the remote mode
  variables.
- **Already marked for removal.** The configuration reference listed
  `module_runtime.pki` and `cert_lifetime` as "the remote module runtime,
  removed with PostgreSQL support" (M2, P4), and the single-binary design
  (`docs/design/single-binary`) lists the runtime for deletion.

## PR C1a: the built-in package hosts run inside Control (class C)

Base: `main` at b5b888c. Step C1a of the class C design. The owner chose on
2026-11-22 at 12:55Z to give up the process isolation of the built-in
package hosts.

### Motive and evidence

- **The isolation protects nothing any more.** Control runs only the
  packages linked into its own binary: package upload and install were
  removed after 4.2, and the remote module runtime went in 2d. Yet every
  built-in package still ran as its own child process (`/proc/self/exe
  package-host <id>`, twelve community plus three commercial). Each request
  went HTTP → kernel gateway → gRPC to the child → package → gRPC back over
  the bridge → database.
- **What still depended on the child process:** the environment (socket
  path, bridge descriptor, response limit, version, identity KEK), SIGTERM
  for shutdown, and stdout/stderr for log prefixes. Nothing else did. The
  host protocol, the bridge and the capability tokens are the same either
  way.

### Changes

1. `pluginhost.ManagerConfig.InProcess`: when it is set, the supervisor
   starts a built-in host (`ArtifactRef.Builtin`) on a goroutine instead of
   executing the binary. Everything around that start is unchanged:
   - the private runtime directory, the host socket and the bridge socketpair;
   - `verifyArtifactRef`;
   - Health before serving, the watchdog, Drain and Stop.

   Stop cancels the host's context. A panic while the host starts is
   recovered and fails only that start.
2. `cmd/server` sets `InProcess` to `runBuiltinHost`. It runs the same
   version check as `package-host` (`builtinpkg.HostVersion`), then
   `builtin.Run`. Built-in commercial hosts register through the same table
   (`builtin.Register`), so they move with this change and the overlay is
   unchanged.
3. `modulesdk.WithInProcess`. An in-process host takes three things from
   the kernel: its settings (`modulesdk.Host.Getenv`), its bridge (the
   socketpair end, `packagebridgesdk.DialFile`) and a logger prefixed with
   `[pkg:<id> v:<version> gen:<n>]`.
   - The settings are exactly the entries a child received. They are not
     read from Control's environment, so the identity host still sees only
     `ANIX_IDENTITY_KEK` from its package environment, as before.
   - The host leaves the process signals alone.

   Shutdown lets in-flight RPCs finish and cuts the rest after the 2 s grace
   period. A child behaves the same way: before, it waited for the kernel's
   SIGKILL. A panic in a package's background `Run` is now logged and ends
   only that work. Before, it would have ended the child, and now it would
   end Control.
4. `identity-platform` reads its settings through `host.Getenv` instead of
   `os.Getenv`.
5. `pluginhostsdk.MaxResponseBytesFrom(getenv)`, the existing function over
   a given lookup.
6. Docs:
   - `plugin-kernel-contract.md`, "Launch and attestation", is rewritten.
     The `/proc/self/exe` re-exec check no longer applies, because nothing
     is executed. The release signature, the embedded-manifest match and
     the version check stay.
   - Also updated: `control-boundary.md`, `runtime.md`, `startup-config.md`,
     `package-extraction.md`, `features.md`, `release-installation.md`,
     UPGRADE and CHANGELOG.

The subprocess path, `package-host` and the gRPC transport stay for now
(design step C1c removes them). The commercial thread is told before C1c
changes `modulesdk.Run`.

### Risk and rollback

- **Crash isolation is gone.** Request panics are still recovered: the
  gRPC recovery interceptor runs in-process too. Panics while a host starts
  and in background `Run` are recovered (item 3). A panic on any other
  goroutine a package starts ends Control, where before it ended only the
  child. The only such goroutine today is the route-configuration poll
  (`pluginhostsdk.Router.Run`) that identity-platform runs beside its key
  rotation: an SDK loop with no package code in it. The commercial
  packages start none.
- **Shared memory and descriptors.** A leak in a package now shows in the
  Control process. No alert depended on per-host accounting.
- **Shutdown.** A host that ignores its context keeps a goroutine until
  Control exits. The supervisor still waits for it on Stop, as it waited
  for a child.
- **Operations.** `ps` shows one process. A host's own log lines lose the
  `stdout`/`stderr` tag (UPGRADE).
- **Rollback:** revert the merge commit, or run the previous release. No
  schema or configuration change.

- **Both ends live in one process.** Since C1a every built-in host runs on
  goroutines of Control, yet each one still opened a private Unix socket,
  served `pluginhost.v1` over gRPC, and the kernel dialed it, marshalled
