# 网络模型：设备、入口、传输、出口、线路

**状态：** 进行中（2026-11-11 定稿，所有者决定 R1–R4）。本文是网络部分今后的方向；
[`../network-model/README.md`](../network-model/README.md) 描述的是下发给 Agent 的网络计划
（`anixops.network.v1`），那一层保持不变。本文改的是 Control 里管理员面对的数据模型。

## 1. 为什么改

网络计划（每台设备一份）已经按入口、传输、出口实现了，但管理员操作的仍是几套叠在一起的
概念，一条「国内入口到境外出口」的线路要由四个对象拼出来：

| 现有概念 | 存放 | 问题 |
| --- | --- | --- |
| 节点与节点协议 | `v2_node`、`v2_node_protocol` | 机器、地址、协议、倍率混在一起 |
| 节点入口、入口池、iWAN 线路 | `v5_node_entry` 等 | 入口地址的补丁，挂在节点上 |
| 转发路由与「加入订阅」 | `v4_kernel_forward_route`、`v5_forward_route_subscription` | 真正承载中转线路，健康、延迟、流量、DNS 切换都挂在它上面 |
| 网络模型文档 | `v4_kernel_network_model` | 内容主要靠自动补全从转发路由推出来 |
| 分流 | `v5_egress_route` | 另起一套中继，不走网络模型的传输 |

## 2. 决定

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| R1 | 「线路」指哪一层 | 线路指入口到出口的整条路，是订阅和计费单位；网卡那层叫上联 |
| R2 | 协议在哪台设备解开 | 线路自动决定，线路上有一个可选字段可以手动改 |
| R3 | 上线节奏 | 在 5.0.x 里渐进四步，每步可回退 |
| R4 | 转发到第三方目标的纯端口转发 | 保留，作为「固定目标」线路 |

## 3. 对象

线路是唯一的产品单位：一组入口、若干段传输、一个出口，加上跑什么协议。订阅、倍率、流量、
健康、延迟都只挂在线路上。

| 对象 | 含义 | 管理员什么时候碰它 |
| --- | --- | --- |
| 设备 | 一台装了 Agent 的机器 | 加机器时 |
| 上联 | 设备上的一块网卡：源地址、网关 | 只有多网卡或 NAT 机器需要 |
| 入口 | 用户连的地址：直连、NAT 映射、经 iWAN | 每台设备默认有一个直连入口，多地址时手动加 |
| 传输 | 两台设备之间的一段链路 | 默认自动建立、多条线路共用 |
| 出口 | 流量上公网的地方：源地址、出口策略 | 每台设备默认有一个 |
| 线路 | 入口 → 经过的设备 → 出口，加协议或固定目标 | 日常操作就是建线路 |

规则：

- **角色属于线路，不属于设备。** 同一台机器在一条线路里是出口，在另一条里可以是中转。
- **直连也是线路。** 入口和出口在同一台设备、没有传输。
- **服务点（R2）。** 协议在线路上第一台用用户态内核终止流量的设备上解开，认证、计费、限速、
  分流都在这里；默认是出口设备。服务点之前的段只转发字节。
- **转发方式由设备决定。** 会被云厂商扫描的机器用内核转发，其余用用户态转发；线路上不选引擎。
- **分流是线路的规则出口。** 线路有一个默认出口，可以再加若干条「这些域名从另一个出口出」。
- **固定目标线路（R4）。** 不跑我们的协议，最后一台设备直接拨向一组固定地址，不进订阅。

## 4. 规划

规划器是不碰数据库的函数：输入全部对象的快照，输出每台设备的网络计划。对每条线路，前面
连续的内核转发设备各得到一条内核转发，之后第一台设备运行端口转发，再往后每一跳是一段传输，
最后一台设备从出口出去或拨向目标。计划的格式就是现在的 `anixops.network.v1`，Agent 和内核
不需要知道「线路」这个概念。

## 5. 四步

| 步骤 | 内容 | 怎么验证 |
| --- | --- | --- |
| 1 | 线路模型（`internal/netline`）；把现有数据读成线路；线路规划出的转发与今天的逐项比较（影子对比），只读接口 `GET /api/v4/kernel/network/lines`，命令 `anix-control forward lines` | 单元测试；生产上 `differences` 为空 |
| 2 | 建表，一次迁移把数据写进新表；规划、订阅、统计改读新表；旧 API 变成薄适配 | 迁移前后每台设备的计划哈希和每个用户的订阅内容相同 |
| 3 | 新 API 与面板的「设备」「线路」两页、网络拓扑图（全球地图与抽象拓扑） | 前端 e2e |
| 4 | 删除旧 API、旧表、旧包；Agent 删分流成员 | CI；删表前备份 |

第 1 步不建表：影子对比先在真实数据上跑，表的字段在第 2 步按对比结果定。

## 6. 第 1 步的换算规则

| 现有数据 | 读成 |
| --- | --- |
| 节点 | 设备，加一个默认直连入口（地址取节点 host）和一个默认出口，两者的 id 都是节点引用 |
| 节点网络设置、上联网卡 | 上联 |
| 节点入口 | 入口（id 为 `<节点引用>/<入口 id>`），入口池原样带过来 |
| 启用的节点协议 | 直连线路 `protocol-<id>`：入口取该设备启用的直连与 NAT 入口，没有则取默认入口 |
| 转发路由 | 线路，id 为路由 id；目标命中某个节点协议时该线路服务这个协议，已加入订阅的显示为「协议名 \| 显示名」 |
| 路由的每一跳 | 线路链上的一跳；跳之间没写传输时得到一条自动传输（`<上一台>><下一台>/<种类>`） |
| 分流路由 | 服务点在其源节点上的每条线路的一条规则出口 |
| 节点出口策略 | 该设备默认出口的 `block_mainland` |

读不成线路的路由（旧引擎、跳上没有节点、同一台设备在一条路由里用内核转发而在另一条里用
用户态）列在 `skipped` 里，并附原因。
