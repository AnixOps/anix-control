# 组网：地区、地址分配与入网凭据需求

状态：需求已确认（2026-11-25）。第一阶段已实现：地区（默认四个，迁移 0045）、服务器段固定地址、边界节点、节点配置下发与状态展示（`internal/meshregion`，门控功能 `mesh`，发布版默认关闭；与 Agent 的接口见 [agent-contract.md](agent-contract.md)）。第二阶段已实现（迁移 0046）：设备地址池与 30 天回收、宿主组与设备命名、内网域名列表（重名全部列出并标记）、地区变更申请与审批、组网设置（域名后缀、宿主组地址范围、保留网段），均在「节点 → 组网」的分区中。入网凭据与无 Agent 设备的配置读取、只读上报和地区变更申请已实现（迁移 0047，接口见 [agent-contract.md](agent-contract.md) 第 4 节）。域名列表与宿主组已下发到节点配置（`dns`、`host_groups`，见 [agent-contract.md](agent-contract.md) 第 2 节）。无 Agent 的完整节点（R32：固定地址、经管理员确认后通告局域网网段）已实现（迁移 0048）。编号沿用项目需求表（R1–R34）。组网模块在内核中实现；本页是面板负责的部分。地区控制面中继与发布文件缓存（R33、R34）由单独的 PR 承载。

## 地区定义（R18、R20、R24、R27）

- 管理员在面板定义地区及各地区的边界节点；默认四个地区：中国大陆、亚太（日本、香港、台湾等不拆分）、欧洲、北美，可增删。
- 每个地区是独立网络，虚拟网段互不重叠；每个地区至少两台边界节点。
- 节点首次入网按延迟自动归属地区；之后的地区变更由节点所有者申请、网络管理者在面板批准后迁移（管理者也可直接发起），迁移会改变节点虚拟地址。
- 地区网络强制启用前向保密（R30）。

## 地址分配（R29）

- 每个地区的虚拟网段划分为服务器段与设备地址池，前缀长度相同。
- 服务器、边界节点、宿主组网关等基础节点使用固定地址，由管理员或 Agent 分配并绑定节点身份。
- 手机和个人电脑由面板从设备地址池分配，按设备身份保持不变，30 天未使用才回收；设备先拿到地址再入网。
- 宿主组使用地区虚拟网段之外的组地址段（R21）。

## 入网凭据与只读上报（R31）

- 面板为节点签发一次性入网凭据（Agent 节点经 Agent 下发，无 Agent 节点经安装命令使用）。
- 受管网络只接纳本平台的内核：Agent 节点、本平台客户端、无 Agent 安装程序与路由器软件包。第三方实现的节点（原版节点）不直接加入受管网络，面板不为其签发凭据或导出配置；迁移期间它们留在旧网络，经本平台节点桥接过渡（R30，2026-11-25 用户决定）。地区网络配置为 `kind: managed`，并带准入清单 `native_keys`：成员节点的静态公钥由 Agent 上报，无 Agent 设备在接入时或接入后首次上报时提交、之后不可更改；吊销或删除设备即移出清单，各节点随即拒绝其会话。清单外的对端握手被拒，节点状态显示「拒绝未准入节点」（`peer_not_native`）。细则见 [agent-contract.md](agent-contract.md) 第 2 至 4 节。
- 面板新增接收无 Agent 节点只读上报（在线状态与延迟）的接口；上报只回状态码，不下发指令。
- 凭据撤销后拒绝上报。

## 无 Agent 完整节点（R32，迁移 0048）

| 项 | 规则 |
| --- | --- |
| 角色 | 签发凭证时选择「接入端」（默认，地址取自设备地址池）或「完整节点」（未安装 Agent 的路由器或服务器）。完整节点必须指定地区。重新接入已有设备时沿用其角色与地址，不可更改。 |
| 固定地址 | 完整节点使用该地区服务器段中的固定地址：签发时指定（须为服务器段内的主机地址且未被成员、设备或其他未使用的完整节点凭证占用），或留空，在接入时取最低的可用地址。指定的地址在凭证使用、撤回或过期前保留，Agent 节点入网时也会避开；地区改网段时清空未使用凭证保留的地址（接入时自动分配），删除地区时一并删除其未使用的凭证。在 PostgreSQL 上，节点、完整节点与设备的地址分配都先锁定所在地区，修改或删除地区也先锁定该地区；涉及多个地区的变更（边界节点、迁移地区）按地区编号升序一次锁定全部地区，死锁或序列化失败时整个事务重试，并发分配不会重复。地区网段、宿主组超网、保留段与完整节点子网的变更依次进行，彼此互不重叠。CI 在 PostgreSQL 上并发运行这些变更。固定地址不会因未使用而回收；迁移地区时取目标地区服务器段中的最低可用地址。 |
| 配置 | 完整节点的配置 `role` 为 `full`，监听 TCP 与 UDP 11010，`subnets.advertise` 为管理员确认的网段。 |
| 通告网段 | 管理员在设备列表中为完整节点确认通告的局域网网段（R17）：私有 IPv4 网段，至多 32 个，不得与任一地区网段、宿主组地址范围、保留网段或其他完整节点已确认的网段重叠。未确认的网段不下发。 |
| 记录 | 设备删除后，完整节点凭证仍保留为记录；未使用的凭证撤回时释放其保留地址。 |

接口：`POST /api/v4/kernel/mesh/enrollments` 增加 `role` 与 `address`；`PUT /api/v4/kernel/mesh/devices/{id}/subnets`（`{"subnets":[…]}`，记入操作日志 `mesh_device_subnets`）。

## 第二阶段规则（迁移 0046）

| 项 | 规则 |
| --- | --- |
| 地区网段 | 所有地区的前缀长度一致（规范 §15.7 第 2 条），新建或修改地区时与已有地区比较。地区代码 2–16 个字符，以字母开头、以字母或数字结尾；有成员或设备的地区不可改代码。 |
| 设备地址 | 地区网段上半部分为设备地址池（去掉最后一个可用地址与广播地址）。最后一个可用地址（如 /16 的 `.255.254`）是该地区的固定解析地址（规范 §15.9.2 第 8 条），不分配给任何节点；地区列表以 `resolver_address` 返回，节点与设备配置以 `dns.resolver_address` 下发；该地址仍被设备占用时暂不下发，地区标记 `resolver_address_held`（「解析地址被占用」）。保留之前已持有该地址的设备标记 `reserved_address`（「占用保留的解析地址」），不参与回收，可在设备列表中「分配新地址」换成地址池中的地址。新设备取最小空闲地址；地址池已满时，才回收连续 30 天未使用的地址中最久未用的一个，原设备失去地址并标记「地址已回收」，可在设备列表中「分配新地址」。「最近使用」在创建、迁区时写入，并在任一组网节点的状态上报列出该地址为对端时刷新。并发分配撞上唯一索引时自动重试三次，仍冲突则返回 409。 |
| 宿主组 | 地址段取自宿主组地址范围（默认 10.127.0.0/16，前缀 /24），与所有地区网段及保留网段不重叠；创建后地址段不变。网关与备用网关须为组网节点，备用网关与网关同一归属地区。 |
| 设备命名 | 宿主组主机使用该组地址段内的地址，由组网关发布；局域网设备使用地区网段与宿主组范围之外的私有地址，由指定网关发布。名称为单个 DNS 标签。 |
| 内网域名 | `名称.地区代码.后缀`，地区为节点或网关的归属地区。节点名按规范 §15.9.2 第 5 条规范化，字符数据固定为 Unicode 15.1.0（`internal/meshregion/nametable-unicode-15.1.0.txt`，由 `config/scripts/gen_mesh_name_table.py` 生成，内核应使用同一份表；文件 SHA-256 为 `f1f486fd79d9fd8b15183a5d4d1a6efa801af64c6744973d0c65ba958010cd7c`，面板测试校验该值，内核尚未引入该表与校验（见 TODO），表变更时两边同步更新），顺序为：逐码点取简单小写映射（U+0130 映射为 `i`，Σ 一律映射为 σ）；字母、数字、连字符以外的 ASCII 字符，以及不是字母（类别 L*）或十进制数字（类别 Nd）的非 ASCII 码点（含组合符号与 15.1.0 未分配的码点）替换为 `-`，不做 NFC；去掉首尾 `-`；结果为纯 ASCII 时截到 63 字节并去掉末尾 `-`；否则转为 `xn--` 加 Punycode（RFC 3492，不做 UTS46 映射），超过 63 字节时逐个去掉编码前的最后一个字符、去掉末尾 `-` 后重新编码，变为纯 ASCII 时按 ASCII 规则处理。规范化后为空的节点不生成域名并单独列出。管理员录入的设备名与命名须本身是有效 DNS 标签。重名条目全部返回并标记 `duplicate`（R28 已定），并以各自的地址全部下发到节点。后缀按规范 §15.9.2 第 1 条（core #370）：去掉末尾一个点、只把 ASCII 字母转小写后比较（不做 Unicode 大小写映射），须位于 `internal` 之下且至少两级（默认 `mesh.internal`），每级 1–63 个小写字母、数字或连字符（面板另要求连字符不在首尾），最长 172 个字符，使全名不超过 253 个字符；根、任何单级后缀（含 `internal`、`local`、`com`）、`arpa` 及其下（含 `home.arpa`）、`local` 及其下和其他后缀一律拒绝。不合规时面板拒绝保存并在界面给出原因；此前已保存的不合规后缀不下发，节点与免 Agent 设备注册应答的 `dns` 节改为 `enabled: false`，不含名称和 `resolver_address`，设置标出 `name_suffix_invalid`，名称列表标出 `suffix_invalid`，设备不显示全名，直到管理员保存合规后缀（内核同样会拒绝不合规后缀的整份配置）。 |
| 地区变更 | 节点经 Agent 上报 `mesh.region_request` 为自己申请（来源 `member`），管理员也可代为申请（来源 `admin`）。每个节点或设备最多一条待处理申请。批准与拒绝只对仍待处理的申请生效，同时到达的第二个决定返回 409。批准时成员迁入目标地区并获得新地址；成员在申请后已被迁移的，须拒绝。管理员直接迁移（节点「迁移地区」或设备「迁移地区」）记为已批准，记录操作者，并结清待处理申请：目标一致则批准，否则拒绝。 |
| 告警 | 已启用且边界节点少于两台的地区，地区列表返回 `warnings: ["few_boundary_nodes"]`（R19）。网段与 100.64.0.0/10 重叠时返回 `shared_address_space`（「位于共享地址段」，规范 §15.4 与其他组网软件共存）：地区列表（地区网段）、设置（宿主组地址范围）、宿主组列表（地址段）、设备列表（完整节点的通告网段）。该范围仍可使用，仅告警；新建地区、修改设置与通告网段的表单在输入此类网段时即提示。 |
| 约束 | 担任宿主组网关或备用网关、或发布设备命名的节点，须先调整这些配置才能迁移或移出组网。有设备的地区不可改网段或删除；有待处理申请指向的地区不可删除。 |

接口均在 `/api/v4/kernel/mesh/` 下：`summary`、`settings`、`devices`（含 `regions/{id}/devices`、`devices/{id}/move` 与 `devices/{id}/address`）、`host-groups`、`device-names`、`names`、`changes`（含 `approve`、`reject`），写操作记入操作日志（模块 `mesh`）。

## 外部网络桥接（迁移 0051，R36，内核 0.4）

规范 §15.12。一台同时位于外部网络（其他组网软件的网络）与我方地区网络的 Linux 节点，把外部网络中的指定地址单向导入本地区，只允许名单中的来源访问。

| 项 | 规则 |
| --- | --- |
| 桥接节点 | 须为组网节点（安装 Agent），在其归属地区桥接，每个节点至多一个桥接配置。担任桥接的节点须先删除桥接配置才能迁移或移出组网。成员列表标为「外部网络桥接」。无 Agent 的完整节点暂不支持（见 TODO）。 |
| 外部网卡 | 1–15 个字母、数字或 `_` `.` `@` `-`。 |
| 通告地址 | 1–64 项。单个地址（IPv4 /32、IPv6 /128）可以位于 100.64.0.0/10 或 fd7a:115c:a1e0::/48 内；子网须在私有地址白名单内（10/8、172.16/12、192.168/16、100.64/10、fc00::/7），且不与 100.64.0.0/10、fd7a:115c:a1e0::/48 重叠；不得与任一地区网段、宿主组地址范围或完整节点的通告网段重叠，反之亦然。不发 `shared_address_space` 告警。两台桥接节点可以通告相同地址（冗余）。 |
| 来源名单 | 至多 256 项，按成员身份配置：`node:<节点>`（其在该地区的地址）、`device:<设备编号>`（持有地址与静态公钥时的地址；撤销的设备没有静态公钥，不再展开）、`host_group:<宿主组编号>`（网关归属该地区时的地址段）。保存时每项须属于桥接节点的地区；之后离开该地区的项不再展开，桥接列表标记 `allow_outside_region`。下发时展开为 `/32` 与地址段（`external_bridge.allow`，见接口约定第 2 节）。 |
| 待桥接确认 | 地址或地址段从某桥接节点的名单中移出（成员移出、删除、撤销、迁移、地址回收，宿主组删除，名单修改，删除桥接）后记为待确认（`v5_mesh_bridge_hold`），不再分配给节点、设备、完整节点或宿主组，直到该节点上报的已生效名单摘要（`mesh.status` 的 `networks[].externalBridge.allowDigest`，算法见接口约定第 3 节）等于面板对当前名单算出的摘要，且生效时间 `appliedAt` 晚于移出时刻。桥接节点离线期间一直保留，桥接列表标记 `bridge_unconfirmed`（「未确认」）并列出这些地址。设备地址池已满且唯一可回收的闲置地址在名单中时，先从原设备收回该地址，本次请求回 `pool_full`，桥接节点确认后才分配；每个地区同时只收回一个。所有组网变更在 PostgreSQL 上先取同一个咨询锁，名单移出与地址分配不会交错。 |

接口：`GET/POST /api/v4/kernel/mesh/bridges`、`PUT/DELETE /api/v4/kernel/mesh/bridges/{id}`（`{"node","interface","routes":[…],"allow":[…]}`，记入操作日志 `mesh_bridge_create`、`mesh_bridge_update`、`mesh_bridge_delete`）。

## 自定义路径（迁移 0054，内核能力 `mesh_paths`）

管理员为地区内的某个成员（起点）指定到另一成员或某个子网（目标）的路径，依次经过 1–6 个途经节点。面板按成员身份保存，下发时再解析为地址，写入起点所在网络的 `routing.paths`（接口约定第 2 节）。

| 项 | 规则 |
| --- | --- |
| 保存 | 表 `v5_mesh_path`：起点 `source_ref`、目标类型 `target_kind`（`peer` 或 `subnet`）、目标 `target`、途经节点 `via`（逗号分隔）。成员写作 `node:<节点>` 或 `device:<设备编号>`，不保存地址；同一起点对同一目标至多一条（唯一索引，重复回 409）。 |
| 起点 | 组网节点（Agent），或角色为完整节点的无 Agent 设备；接入端设备不可作起点。起点的地区即其归属地区，创建后不可更改。 |
| 目标 | 对端：同一地区的任一成员（接入端设备可作目标），不得是起点自身。子网：私有地址范围内的 IPv4 网段，不得与起点地区网段重叠，也不得落在宿主组网段内且前缀更长（宿主组成员跟随网关的路径，只能以整个宿主组网段为目标）。 |
| 途经节点 | 1–6 项，不重复，不得是起点或对端目标；须为同一地区的组网节点或完整节点设备，接入端设备不可作途经节点。 |
| 下发 | 对端 `{"to_peer": "<虚拟地址>", "via": [...]}`，子网 `{"to_subnet": "<CIDR>", "via": [...]}`，按编号顺序。起点、目标或任一途经节点解析不到当前地区内的地址（已离开地区、设备被删除或失去完整节点角色、没有地址）时，该条不下发，列表标记 `path_member_missing`。 |
| 能力 | Agent 节点的路径由 Agent 按内核能力名单处理（不列出 `mesh_paths` 的内核得到空列表）。无 Agent 的完整节点设备只在最近一次上报或读取配置时的能力名单列出 `mesh_paths` 时才下发路径，否则 `paths` 为空，列表标记 `path_unsupported`。 |
| 清理 | 删除设备或节点移出组网时，凡以其为起点、目标或途经节点的路径一并删除（同一身份以后重新加入时不继承旧路径），设备删除与成员移出的审计内容带 `paths_deleted`；节点或设备迁移到其他地区时，以其为起点的路径删除，仅作为目标或途经节点出现的路径保留并标记 `path_member_missing`。 |
| 状态 | 取起点最近一次 `mesh.status` 中该地区网络的 `paths[]`，条目 `id` 为 `peer:<目标地址>` 或 `subnet:<CIDR>`。列表原样给出 `state`、`reason`、`unreachable`，界面将 `active` 显示为「按自定义路径」、`first_hop_only`「仅保证首段」、`fallback`「已回落」、`pending`「检测中」。 |
| 宿主组 | 子网目标不得位于宿主组网段之内且前缀更长（内核会拒绝起点的整份配置）。保存路径与新建宿主组都先取地址规划锁，相互校验：指定网段包含已有路径的子网目标时拒绝新建宿主组（`409`），自动选段时跳过这类网段；此前已存在的冲突在下发时按当前宿主组重新校验，跳过该路径并标记 `path_target_in_host_group`。 |
| 准入 | 途经节点在本地区尚无静态公钥（未进入准入清单 `native_keys`）时标记 `path_waypoint_not_admitted`，路径照常下发，内核在其准入前回落。 |
| 地址族 | 子网目标目前只支持 IPv4。 |

接口：`GET/POST /api/v4/kernel/mesh/paths`、`PUT/DELETE /api/v4/kernel/mesh/paths/{id}`（`{"source","target","via":[…]}`，`target` 为成员或 CIDR，更新时 `source` 不得改变；记入操作日志 `mesh_path_create`、`mesh_path_update`、`mesh_path_delete`）。校验失败回 400，同一起点与目标重复回 409，未知编号回 404。

## 区域目录、自动选区与迁区建议（迁移 0055–0058，内核能力 `mesh_region_probe`、`mesh_region_request_state`）

协议见 networkcore `docs/protocols/intranet-mesh-appendix.md` D 节；接口字段见接口约定第 2、4、5 节。

| 项 | 规则 |
| --- | --- |
| 偏好区域（D.5） | 入网凭据可带 `preferred_region`（地区代码，签发时校验存在；与 `region_id` 或 `device_id` 同时给出回 400）；组网设置 `preferred_region` 为全面板默认。凭据未指定地区时，面板对每个已启用且有时延的地区算 `score = 时延 × 0.8`（偏好区域，凭据的优先于默认）或 `score = 时延`，取最小者，得分相同依次按 `sort`、`id` 升序（`chooseRegion` 显式排序，不依赖列表顺序）；没有任何已启用地区有时延时回 400。地区被删除后其偏好视为没有。表列：`v5_mesh_enrollment.preferred_region_id`、`v5_mesh_settings.preferred_region_id`（可空）。 |
| 探测应答器端口 | 组网设置 `responder_port`，默认 11013（1–65535，不得等于组网端口 11010）；`v5_mesh_settings.responder_port` 可空，空为默认。 |
| 目录（D.2） | `GET /api/v5/mesh/device/directory`；Agent 节点的目录随配置下发。只列已启用地区中、有边界节点（主成员行 `boundary` 为真）且该节点最近一次 `mesh.status` 的 `region_probe.responder.public_key` 合规（44 字符标准 base64，解码 32 字节，非全零）、且有可探测地址的项；一个地区没有这样的边界节点就整个省略。`borders[].probe` 取节点的单播 IP 字面量（依次为 `server_ip`、`last_public_address`、`host`，不解析主机名；内网地址允许）加响应端口，IPv6 加方括号；`name` 为节点名按 §15.9.2 规范化得到的 DNS 标签，为空时 `node-<节点>`，同一地区重名时附 `-<节点>`。至多 64 个地区、每地区 16 个边界节点。 |
| 区域对象（D.9.1） | `current` 为已下发网络的归属地区代码（该地区网络未下发，例如地区停用时为 `null`），`basis` 为 `latency`（按时延选区）、`credential`（凭据指定）、`admin`（管理员指定或移动）、`migration`（节点申请经批准迁入）。保存在 `v5_mesh_member.region_basis`（主成员行）与 `v5_mesh_device.region_basis`，空按 `admin`。Agent 节点另在 `responder` 给出 `{"listen": ["0.0.0.0:<端口>", "[::]:<端口>"]}`，只对边界节点。 |
| 能力门控 | 设备：只有设备的内核能力名单（查询参数 `features`，否则最近一次上报，接入应答用请求体的 `features`）列出 `mesh_region_probe` 时配置才带顶层 `region`，列出 `mesh_region_request_state` 时才带网络内的 `region_request`；设备拒绝未知字段，门控须精确。Agent 节点：面板始终下发（同 `dns`、`external_bridge`），Agent 按内核能力名单省略。 |
| 自动选区的 Agent 节点（D.5 第 2 条） | 管理员 `POST /api/v4/kernel/mesh/auto-members {"node": "proxy-<id>"}` 把未入网的节点加入「待选区」（表 `v5_mesh_auto_node`，节点唯一，已入网或已待选区回 409；`GET` 列出，`DELETE .../auto-members/{id}` 取消）。待选区节点的成员 `mesh` 为 `{"networks": [], "region": {"current": null, "basis": null, "directory": …}}`。节点的 `mesh.status` 带 `region_probe.regions`（`[{region, rtt_ms}]`）且至少一个已启用地区有时延时，面板用同一选区函数（默认偏好区域）选区，在选定地区的锁下按 AddNode 的方式分配服务器段固定地址（基础 `latency`，非边界），删除待选区记录并推送配置。管理员此后直接 `AddMember` 同一节点则取代待选区。 |
| 撤回（D.7 第 2 条） | 设备 `DELETE /api/v5/mesh/device/region-change`、Agent 的 `mesh.region_request` 载荷 `{"withdraw": true}`：待审批的申请记为 `withdrawn`（保留在地区变更历史，列表可按该状态过滤），仍被显示的被拒申请也记为 `withdrawn` 而清除 `region_request`；没有申请时也成功。 |
| `region_request`（D.7 第 3 条） | 每个网络（Agent 节点为主地区网络）带 `null`，或该成员最近一条地区变更为 `pending`、或为 `rejected` 时的 `{id（字符串）, region（目标地区代码）, state, reason, reject_reason（被拒时为管理员备注）}`；之后有更新的变更（批准、撤回、管理员移动）即为 `null`。节点的申请、驳回、撤回都立即推送该节点配置。 |
| 迁区建议（D.6、D.9.2） | 节点或设备上报的 `region_probe` 随状态原样保存；设备上报校验 `suggestion` 为 `null` 或 `{region, current_median_ms, suggested_median_ms, since}`（地区代码、非负整数毫秒、RFC 3339 时间），不合规回 400，其他顶层字段不拒绝。成员列表与设备列表的 `region_suggestion` 为 `null` 或该对象，仅作提示，面板不据此移动。 |
